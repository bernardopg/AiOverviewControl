# 2.2.2: Claude usage no longer looks live when it is not

This release for DMS 2.0 fixes the Claude card showing an old usage snapshot as
if it were current ([#89](https://github.com/bernardopg/AiOverviewControl/issues/89),
[#90](https://github.com/bernardopg/AiOverviewControl/pull/90)). Settings,
Claude profiles, pins and history carry over unchanged. Version authority
remains `plugin.json`; the published release body comes from the matching
section in `CHANGELOG.md`.

Thanks to [@TMS-Namespace](https://github.com/TMS-Namespace) for the report:
the matching reset time next to a different weekly percentage pointed straight
at the cause.

## Upgrading

- Requires DMS 2.0 or newer, as 2.2.0 does. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
- No restart is needed beyond the usual plugin reload: only the shell
  adapters changed.

## User-visible changes

### Claude: a fallback snapshot reads as stale

The Claude card reads its limits from Anthropic's OAuth usage endpoint. That
endpoint is rate-limited per account, a limit it shares with Claude Code
itself, and often answers `HTTP 429`. On such a transient failure (429, 5xx or
a network error) the adapter keeps the card useful by reusing the last good
snapshot instead of showing an error.

Before this release that snapshot was stamped with the current time. The card
kept its **Live** badge and a fresh **Updated** time, so its percentages could
trail Claude Code's for as long as the endpoint kept failing (weekly 79% in
the card against 89% in Claude Code in #89). The reset countdown still looked
right because the reset time is an absolute date, and a manual refresh hit the
same 429.

Now:

- The snapshot keeps the time it was fetched as `usage.updatedAt`. After two
  refresh intervals the card shows the **Stale** badge and the real
  **Updated** time, as every other provider already did.
- A window whose reset passed since the snapshot was taken reads 0% with no
  reset time, instead of carrying its pre-reset percentage into the new window
  and raising an alert for it.
- As soon as a request succeeds again, the next refresh shows live numbers.

[Troubleshooting](../troubleshooting.md#claude) explains how to confirm that
the endpoint is rate-limiting you.

## Maintenance

- `get-claude-usage` emits `USAGE_UPDATED_AT` (epoch seconds of the shown
  snapshot), which `providers/native/claude.bash` turns into `usage.updatedAt`.
  The three Claude windows now go through one `window()` helper.
- `tests/test-cov-b-claude.sh` serves an old snapshot through a 429 and checks
  its original `updatedAt`, an untouched future window and a zeroed expired
  window, then a live fetch stamped with the current time.

## Validation and limitations

- Every shell suite, the QML runtime suite under the pinned DMS, the metadata
  and changelog gates, and statement coverage pass in CI.
- The 429 behaviour was reproduced against the live endpoint. The plugin does
  not retry or back off on its own beyond the existing 120 s cache, so while
  the account stays rate-limited the card stays stale; Claude Code's own
  numbers come from its API responses and are not readable from outside it.
