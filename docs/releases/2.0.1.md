# 2.0.1: Claude Code details for every profile

This patch release for DMS 2.0 gives every Claude profile the full **Claude
Code details** panel that only the default account had before. It also stops
interrupted helpers from leaving files behind in the plugin cache. Settings,
Claude profiles, pins and history carry over unchanged. Version authority
remains `plugin.json`; the published release body comes from the matching
section in `CHANGELOG.md`.

Thanks to [@ianptkcs](https://github.com/ianptkcs) for the per-profile details
panel ([#60](https://github.com/bernardopg/AiOverviewControl/pull/60)), their
first contribution to the project.

## Upgrading

- Requires DMS 2.0 or newer, as 2.0.0 does. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
- Run `dms restart` once after upgrading. The update changes the
  `ClaudeProfiles.js` module, and a plain plugin reload can keep the old copy
  cached until the shell restarts.

## User-visible changes

- **Claude Code details for every profile**
  ([#60](https://github.com/bernardopg/AiOverviewControl/pull/60)): each
  `claude-*` profile card now has its own details panel, built from that
  profile's own `CLAUDE_CONFIG_DIR`. The panel shows the tier, session, weekly
  and model-scoped windows with burn-pace forecasts, today/week/month tokens and
  cost, the projected month, the 7-day chart, models this week, top projects
  and all-time totals. Before, profiles showed only their quota bars plus a
  week-tokens / today-cost summary, and the full panel was reserved for the
  default `claude` card. The two summary tiles are gone; their values are in
  the panel. See
  [Multiple Claude accounts](../configuration.md#multiple-claude-accounts).
- **Local analytics survive OAuth failures:** when the Claude usage request is
  rejected or fails, the card still shows its error, and the details panel keeps
  the local history and costs read from transcripts, as
  [troubleshooting](../troubleshooting.md) already described.

## Fixes

- **One Claude helper per account and refresh:** the default account used to
  run `get-claude-usage` twice per refresh, once in the dispatcher and once in a
  separate details process that fed global widget state. The details now come
  from each provider's own dispatcher item, and the extra process, its timeout
  and its two error strings (removed from all five locales) are gone.
- **Shared Claude caches are replaced atomically:** profiles refresh in
  parallel, so the shared pricing and CLI-version caches are now written through
  `mktemp` + `mv`. A concurrent reader can no longer catch a truncated pricing
  file and show $0.00 for a cycle.
- **No more files left in the cache by interrupted helpers**
  ([#61](https://github.com/bernardopg/AiOverviewControl/pull/61)):
  - A Claude refresh killed mid-parse (refresh timeout, shell restart) left a
    partial `claude-transcripts.tsv.XXXXXX` copy of several megabytes. An exit
    trap now removes it. Each run also drops leftovers from earlier kills while
    it holds the per-account lock.
  - The unscoped `claude-transcripts.tsv` and `claude-usage-cache.json` at the
    cache root, replaced by per-account copies in 1.22.0 and no longer read,
    are removed.
  - A quota alert whose helper was terminated while waiting for a click
    (logout, shell restart) left one `.notify-waiter.*` file each. An exit trap
    now removes it, and widget start-up sweeps files that a killed helper left
    behind and that no process still holds open.

  On an affected install the first refresh after upgrading reclaims the space
  (tens of megabytes were seen in practice). Nothing to do by hand.

## Validation

- New fixture coverage:
  - `test-claude-profiles.sh`: per-profile models, projects, tier and scoped
    model, analytics kept on a 401, one transcript cache per config dir.
  - `test-qml-smoke.sh`: `ClaudeProfiles.details()`.
  - `test-widget-runtime.sh`: per-profile panels render with their own data.
  - `test-claude-cache.sh`: no temp file left by a run, by a run killed
    mid-parse, or by an earlier kill.
  - `test-quota-alert.sh`: a terminated helper removes its waiter file, and the
    start-up sweep keeps waiter files a live process holds.
- All 32 offline suites pass, along with shell syntax and shellcheck, the
  metadata, changelog and badge gates, `qmllint` against the DMS 2.0 imports,
  actionlint, gitleaks, the packaging checks and the real DMS UI suite.
- Verified live with two real Claude accounts (`claude` plus one `claude-*`
  profile): each card shows its own details panel with its own tier, models and
  projects.

## Limitations

- The shared pricing and version caches have no cross-account lock, so a helper
  killed with SIGKILL during their atomic replace can still leave a small temp
  file next to them.
- After a plugin reload without `dms restart`, `ClaudeProfiles.js` may stay
  cached.
