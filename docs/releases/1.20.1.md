# 1.20.1: OpenCode v2 and reliability fixes

This patch release restores local telemetry for OpenCode v2, repairs manual
checkout installs, refreshes provider health automatically and removes two
optional desktop dependencies. It does not change settings, credential formats
or stored history. Version authority remains `plugin.json`; the exact published
release body comes from the matching section in `CHANGELOG.md`.

Thanks to [@ReillyBrogan](https://github.com/ReillyBrogan) for reporting the
OpenCode v2 failure ([#46](https://github.com/bernardopg/AiOverviewControl/issues/46))
and contributing the OpenCode and settings/install fixes
([#47](https://github.com/bernardopg/AiOverviewControl/pull/47),
[#48](https://github.com/bernardopg/AiOverviewControl/pull/48)).

## User-visible changes

- **OpenCode v2 telemetry:** OpenCode v2 keeps `opencode.db` but writes sessions
  to `session_v2` and assistant messages to `session_message`, with model data
  nested under `model.{id,providerID}`. The local analytics reader now detects
  the available generations and reads both safely. A session present in v2 is
  counted there once; a legacy-only v1 session remains visible after an
  in-place upgrade. Existing v1-only installations are unchanged. See
  [provider details](../providers.md#opencode).
- **Complete checkout installs:** the manual command now copies all root QML
  components and `scripts/`. Older instructions omitted five QML files and the
  local analytics filter, so an installation could load but fail at runtime.
  Checkout users should repeat the command in the
  [installation guide](../installation.md#install-from-a-checkout).
- **Provider readiness:** settings now reload the persisted provider selection
  when DMS injects `pluginService`, then re-run health checks whenever the
  effective selection changes. Provider rows no longer remain on `Checking…`
  until a manual re-check.
- **Optional desktop tools:** quota notifications prefer `notify-send` but fall
  back to `dms notify`, so libnotify is optional. The Antigravity IDE session
  reader now uses coreutils instead of `strings`, removing the binutils
  dependency.
- The MIT license now names the correct copyright holder.

## Privacy, migration and compatibility

- No setting, credential or cache migration is required.
- OpenCode databases are opened read-only. The adapter reads usage metadata
  (`tokens`, `cost`, model, timestamps and working directory), never message
  content.
- A missing OpenCode cost remains unknown (`—`), distinct from a recorded zero
  cost.
- `dms notify` preserves quota-alert deduplication and cooldowns. Unlike
  `notify-send`, it cannot replace an existing popup, set urgency or attach the
  action that focuses a provider card. Systems with libnotify keep the full
  behavior.

## Maintenance and validation

- `tests/test-local-analytics.sh` covers v1-only and v2 data, nested model
  attribution, tokens, cache reads, recorded and unknown costs, legacy-only
  sessions and duplicate suppression across schema generations.
- `tests/test-widget-runtime.sh` covers late `pluginService` injection,
  selection-driven health refresh and exact IPC responses under an isolated
  UTF-8 locale.
- `tests/test-metadata.sh` rejects checkout instructions that omit a root QML
  component or `scripts/`.
- All 26 offline suites, shell syntax and shellcheck, metadata/changelog gates,
  `qmllint`, actionlint, packaging, and the real DMS UI suite under headless sway
  are required before publication.

## Limitations

- OpenCode schema detection follows the v1 `session`/`message` and v2
  `session_v2`/`session_message` generations present in OpenCode 2.x. A future
  incompatible schema fails as an explicit unsupported-database error rather
  than showing zero usage.
- Legacy rows whose session id also exists in v2 are intentionally ignored;
  OpenCode freezes the old generation during upgrade, and summing both would
  double-count the same session.
- The `dms notify` fallback has the interaction limitations described above;
  install libnotify when clickable provider-focus actions are required.
