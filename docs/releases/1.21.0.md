# 1.21.0: Neuralwatt, live Cline data and honest free-tier limits

This feature release adds Neuralwatt as a provider. It also turns Cline from a
link-only card into live account data, and makes the NVIDIA card verify its key
for real. Free-tier users get the limits the APIs actually expose: OpenRouter's
daily `:free` model allowance, and an opt-in Groq rate-limit probe. No setting,
credential or history migration is required. Version authority remains
`plugin.json`; the published release body comes from the matching section in
`CHANGELOG.md`.

Thanks to [@SlobCoder](https://github.com/SlobCoder) for the Neuralwatt request
and its schema notes ([#50](https://github.com/bernardopg/AiOverviewControl/issues/50)).

## User-visible changes

- **Neuralwatt (new provider):** one read-only `GET /v1/quota` call with
  `NEURALWATT_API_KEY` shows three things:
  - The subscription kWh allowance for the billing period. It is measured on the
    billed basis and shows 100% while in overage.
  - The prepaid USD balance, as `remaining / total`.
  - The optional per-key spending allowance, which shows 100% when blocked.

  Prepaid-only accounts lead with the balance. See
  [provider details](../providers.md#neuralwatt).
- **Cline:** the card reads Cline's account API, the one its CLI and IDE use. It
  shows:
  - The credit balance of the personal account or the active organization.
  - A **Today** line with requests, tokens, free-model requests and billed
    credits.
  - The ClinePass plan and its renewal date.

  Credentials come from `CLINE_API_KEY`, or from the Cline CLI sign-in while its
  one-hour token is valid. See [provider details](../providers.md#cline).
- **NVIDIA:** the public models catalog answered 200 to any key, so the card
  could not tell a bad key from a good one. The adapter now uses NGC's
  caller-info endpoint, the one the official `ngc` CLI uses. It rejects an
  invalid or revoked `nvapi-` key and names the key type and owner for a valid
  one. NVIDIA still publishes no credits or rate-limit API.
- **Groq (opt-in):** Groq has no usage or limits API, and reports limits only in
  the headers of a served completion. Set `GROQ_QUOTA_MODEL` (for example
  `openai/gpt-oss-120b`) to show two bars: requests per day and tokens per
  minute. To read them, the adapter sends one 1-token completion every 30
  minutes (`GROQ_QUOTA_TTL`) and caches the result. See
  [provider details](../providers.md#groq).
- **OpenRouter:** for keys without a spending cap, the bar now shows the daily
  `:free` model request allowance (`free_model_daily_requests`), which resets at
  00:00 UTC. Capped keys keep their cap.

## Privacy, migration and compatibility

- No migration is required. Existing cards keep their settings.
- **Cline:** the plugin reads the CLI's `providers.json` but never refreshes the
  token and never writes to Cline's data directory, because a refresh can rotate
  the refresh token and sign the CLI out. Once the token expires, the card asks
  you to run `cline` once. For an unattended card, use `CLINE_API_KEY`.
- **NVIDIA:** the key is sent to NGC in the request body from stdin, never in a
  process argument or a URL. If NGC is unreachable, the card shows an unverified
  note instead of an error.
- **Groq:** the probe is off unless `GROQ_QUOTA_MODEL` is set.
  - Each probe counts against the limit it measures: about 48 requests a day at
    the default interval.
  - Other apps that use the same key and model show up in the remaining count.
  - Cached probe results live in
    `${XDG_CACHE_HOME:-~/.cache}/AiOverviewControl/`.

## Maintenance and validation

- New suites `tests/test-neuralwatt.sh`, `tests/test-cline.sh`,
  `tests/test-nvidia.sh` and `tests/test-groq.sh` are registered in CI, and
  `tests/test-openrouter.sh` is extended. Together they cover:
  - The Cline usage-log paging and its organization path.
  - Expired Cline tokens, which never reach the network.
  - The NVIDIA key travelling only on stdin.
  - Groq opt-in, caching and 429 handling.
- The new adapters also pass under jq 1.7, the version on the Ubuntu CI runners.
- All 30 offline suites pass, along with:
  - Shell syntax checks and shellcheck.
  - The metadata and changelog gates.
  - `qmllint` and actionlint.
  - The packaging checks.
  - The real DMS UI suite under headless sway.

## Limitations

- **Cline:**
  - The daily free-model limit has no published number. Cline reports it only as
    a `429 Free limit reached on model …` at inference time, so the card shows a
    count, not a bar.
  - ClinePass has no usage-limit endpoint.
  - The Today line reads at most 1,000 requests and is marked `≥N` beyond that.
- **Neuralwatt:**
  - Only the error path was checked against the live API; the success path is
    covered by fixtures built from the documented example response.
  - The daily energy and carbon breakdown (`/v1/usage/energy`) is not shown.
- **Groq:**
  - The probe reports requests per day and tokens per minute, the only limits
    its headers carry.
  - RPM, TPD and audio-seconds limits are not shown.
  - The daily counter refills continuously, so its reset time is when it will
    be full again, not midnight.
