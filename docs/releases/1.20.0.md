# 1.20.0: Cursor usage and OpenRouter key limits

This is a feature release. It adds real usage for Cursor and fixes the
OpenRouter key-limit bar. It does not change settings, credential formats or
stored history. Version authority remains `plugin.json`. The exact published
release body comes from the matching section in `CHANGELOG.md`.

Thanks to [@SkippySteve](https://github.com/SkippySteve) for the Cursor
adapter ([#39](https://github.com/bernardopg/AiOverviewControl/pull/39)) and
to [@gtheys](https://github.com/gtheys) for reporting and fixing the
OpenRouter limit ([#40](https://github.com/bernardopg/AiOverviewControl/issues/40),
[#41](https://github.com/bernardopg/AiOverviewControl/pull/41)).

## User-visible changes

- **Cursor usage:** the Cursor card was informational at 0%. It now shows the
  included usage of the signed-in account, as on the cursor.com included-usage
  screen: **Cursor Models** and **Other Models**, both resetting with the
  billing cycle, plus **On-demand** when that spend is enabled. The
  `used / limit` plan ratio is deliberately not a bar, because it can read
  100% while both pools are still partly used. Accounts still on request
  quotas fall back to the older per-model request count. Cursor stays opt-in:
  add `cursor` to the provider selection. See
  [providers](../providers.md).
- **OpenRouter key limit:** a key with a daily, weekly or monthly limit read
  100% (and fired quota alerts) forever once its lifetime spend passed the
  limit, because OpenRouter reports `usage` as lifetime spend. The bar and its
  `$used / $limit` value now measure the current window: `limit` minus
  `limit_remaining`, or the `usage_daily` / `usage_weekly` / `usage_monthly`
  counter matching `limit_reset`. Keys without a reset keep lifetime spend.
- New window labels (Cursor models, On-demand, Plan) are localized in all
  five languages.

## Privacy and network

- The Cursor adapter only reads the session that the Cursor IDE
  (`state.vscdb`, opened read-only) or `cursor-agent` (`auth.json`) already
  stored. It sends that session only to `cursor.com`, never writes, refreshes
  or logs it, and does not call the dashboard when the token has expired.
- `CURSOR_STATE_DB` and `CURSOR_AUTH_FILE` pin the session source; the tests
  use them so they never read a developer session.

## Maintenance and validation

- `tests/test-cursor-usage.sh` covers both pools, on-demand, the request-quota
  fallback, unlimited plans, string and epoch cycle bounds, 401/429/500 and
  parse errors, expired and missing sessions, and provider health.
- `tests/test-openrouter.sh` covers windowed limits, a missing
  `limit_remaining`, lifetime caps and keys without a limit. All 26 suites
  run offline.

## Limitations

- Cursor publishes no individual quota API. The adapter uses the dashboard's
  `cursor.com/api/usage-summary` route, which is undocumented and can change
  without notice; failures surface as a structured error card, never as 0%.
- Cursor team and Enterprise admin usage is not covered.
