# 2.2.1: Several quota windows in the DankBar

This release for DMS 2.0 lets the DankBar pill show more than one quota window
of a provider at once, such as Claude's 5 hour and 7 day limits side by side
([#86](https://github.com/bernardopg/AiOverviewControl/issues/86),
[#87](https://github.com/bernardopg/AiOverviewControl/pull/87)). Settings,
Claude profiles, pins and history carry over unchanged. Version authority
remains `plugin.json`; the published release body comes from the matching
section in `CHANGELOG.md`.

Thanks to [@guidi-injenia](https://github.com/guidi-injenia) for the request
and its clear description of the display it needed.

## Upgrading

- Requires DMS 2.0 or newer, as 2.2.0 does. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
- **Run `dms restart` once after upgrading.** The release adds a JavaScript
  module, `BarWindows.js`, that a running shell does not pick up on a hot
  reload: `dms ipc call plugins reload aiOverviewControl` fails with
  `File name case mismatch` and leaves the plugin disabled until the shell
  restarts.
- Existing `barWindowOverrides` values keep their meaning. Nothing changes in
  the bar until you pick one of the new choices.

## User-visible changes

### Several windows per provider in the DankBar

**Settings → DankBar usage window** has two new choices per provider, next to
Primary, Secondary, Tertiary and Highest:

| Choice | Stored as | The pill shows |
| --- | --- | --- |
| Primary + secondary | `claude:primary+secondary` | Claude's 5 hour and 7 day windows: `5h 45% / 7d 80%` |
| All windows | `claude:all` | Every window the provider reports, including Claude's model-scoped 7 day limit when there is one |

- Each window is tagged with its length and coloured on its own, so a nearly
  spent weekly window shows in orange next to a green session window. The tag
  follows the plugin language (`5 Std. / 7 T.` in German, `5小时 / 7天` in
  Chinese).
- On a vertical bar the tag sits above each percentage.
- Hovering the pill names every window, and adds each reset time when the pill
  tracks one provider: `Claude · Session · 30% · resets in 2h · Weekly · 70% ·
  resets in 3d`.
- The `top` and `auto` pill modes rank such a provider by its highest window.
- With the default **Windows that raise alerts** (`displayed`), each shown
  window raises its own alert.
- A window missing from the provider's data is skipped. When none of the chosen
  windows exists, the primary window is shown, so a choice never blanks the
  bar.
- Sets can also be written by hand in `barWindowOverrides`, in any order:
  `claude:secondary+primary` is stored as `claude:primary+secondary`, and all
  three windows as `claude:all`. See
  [Configuration](../configuration.md) and [Usage](../usage.md).

### Settings text

- **Windows that raise alerts** describes the displayed windows in the plural,
  in every language.
- The **DankBar usage window** description keeps its `5h 45% / 7d 80%` example
  on one line in German and Spanish.

## Maintenance

- Slot parsing moved into `BarWindows.js`, shared by the widget and the
  settings page, which each carried a copy before. The release packaging check
  requires the module in the archive.
- `tests/test-qml-smoke.sh` checks the module directly, and
  `tests/test-widget-runtime.sh` renders the real horizontal and vertical pills
  with two windows and checks the stored settings value.

## Validation and limitations

- Every shell suite, the QML runtime suite under the pinned DMS, the metadata
  and changelog gates, and statement coverage pass in CI.
- Checked by hand on a live DMS 2.0 session: both new choices in the bar and
  the tooltip, returning to Primary, and the settings page, pill and dashboard
  in English, Portuguese, German, Chinese and Spanish.
