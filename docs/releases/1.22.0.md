# 1.22.0: Claude profiles, remaining quota and a hardened supply chain

This feature release lets one desktop track several Claude subscriptions side by
side, and lets every quota indicator show what is left instead of what is used.
It also hardens how the plugin is built and published: secret and workflow scans
on every change, signed build provenance for the release archives, and a
seven-day quarantine for new upstream tooling. Existing settings keep working.
Upgrading needs one `dms restart` because the plugin ships a new JavaScript
module. Version authority remains `plugin.json`; the published release body
comes from the matching section in `CHANGELOG.md`.

Thanks to [@mmoya](https://github.com/mmoya) for the multiple-accounts request
([#54](https://github.com/bernardopg/AiOverviewControl/issues/54)) and to
[@trnqq-0](https://github.com/trnqq-0) for the remaining-quota request
([#53](https://github.com/bernardopg/AiOverviewControl/issues/53)).

## User-visible changes

- **Claude profiles** ([#54](https://github.com/bernardopg/AiOverviewControl/issues/54)):
  add up to 16 named Claude accounts under **Settings → Claude profiles**. Each
  profile has its own provider ID (`claude-work`, `claude-personal`, …) and
  reads only its own `CLAUDE_CONFIG_DIR`. A profile gets everything a provider
  has:
  - Its own card, quota windows and a week-tokens / today-cost summary.
  - Its own readiness check, pin, DankBar window override and alert threshold.
  - Its own notifications and IPC focus target
    (`dms ipc call aiOverviewControl focus claude-work`).

  The ordinary `claude` provider is unchanged: it still reads the shell's
  `CLAUDE_CONFIG_DIR`, or `~/.claude`. The full model and project breakdown
  stays on that default card. See
  [Multiple Claude accounts](../configuration.md#multiple-claude-accounts).
- **Show remaining quota** ([#53](https://github.com/bernardopg/AiOverviewControl/issues/53)):
  a new setting (`showRemainingQuota`, off by default) shows `100 − used` in
  the DankBar pill, its tooltip and the dashboard quota bars and rings. The
  dashboard and tooltip label the value as **left**. Colors, alert thresholds,
  provider ranking, fleet load and peak, history charts and notifications keep
  using consumption, so a provider close to its limit still turns red and
  alerts exactly as before.
- **Title:** the dashboard and settings show the plugin's real name,
  **AiOverviewControl**, in every language instead of the old working name.

## Setting up a second Claude account

1. Sign the account in to its own directory:

   ```bash
   mkdir -p ~/.claude-work
   CLAUDE_CONFIG_DIR="$HOME/.claude-work" claude auth login --claudeai
   CLAUDE_CONFIG_DIR="$HOME/.claude-work" claude auth status
   ```

2. Optionally add a shell shortcut, so `claude` and `claude-work` can run at
   the same time in different terminals:

   ```bash
   claude-work() { CLAUDE_CONFIG_DIR="$HOME/.claude-work" command claude "$@"; }
   ```

3. Run `dms restart` once after upgrading to 1.22.0.
4. In **Settings → Claude profiles**, enter the provider ID `claude-work`, a
   display name and the absolute directory (for example
   `/home/you/.claude-work`; `~` and `$HOME` are not expanded). Then select
   **Add Claude profile**. The profile is tracked right away.

To share settings, rules or skills between accounts, symlink those entries from
`~/.claude` into the new directory. Never link `.credentials.json`, `projects/`
or the whole directory: that would mix the accounts and their analytics.

## Privacy, migration and compatibility

- **One restart:** a Quickshell process started before the upgrade cannot
  load the new `ClaudeProfiles.js` module during a hot reload. Run
  `dms restart` once; later profile changes only need a refresh.
- **Credentials** stay in each account's own directory and are sent only to
  Anthropic's OAuth usage API. Plugin settings store only the profile name and
  directory, never a token.
- **Caches:** Claude usage snapshots and transcript caches now live under
  `${XDG_CACHE_HOME:-~/.cache}/AiOverviewControl/claude-profiles/<sha256 of the
  canonical directory>/`. Two accounts never share a snapshot, and two
  spellings of one directory (for example through a symlink) share one. The
  old unscoped snapshot is no longer trusted, so the first refresh after the
  upgrade fetches fresh data. Pricing and CLI-version caches stay shared.
- **Tokens:** the plugin never refreshes an OAuth token. A profile left unused
  for days can show *credentials invalid or expired*; running that account's
  `claude` once renews it.
- **Removing a profile** clears its selection, pin, custom-pill entry and
  window or alert overrides. It does not delete credentials, caches or history.
  To change a profile's directory, remove it and add it again.

## Security and supply chain

- **Release provenance:** the Release workflow now signs
  [SLSA build provenance](https://slsa.dev/) for the `.zip` and `.tar.gz`.
  Verify a download with
  `gh attestation verify AiOverviewControl-v1.22.0.zip --repo bernardopg/AiOverviewControl`.
  The release is published by the runner's `gh release create --verify-tag`,
  so no third-party action holds write access to the repository.
- **Secret scan** (new required check): gitleaks over the full Git history with
  redacted output, and TruffleHog reporting only credentials their issuer still
  accepts. It runs on every PR, push to `main` and weekly. The optional
  pre-push hook also runs gitleaks on outgoing commits when it is installed.
- **Workflow security audit** (new required check): zizmor fails the build on
  medium or higher findings. The audit led to these fixes:
  - The release no longer forwards every repository secret to CI
    (`secrets: inherit`); it passes only `CROWDIN_API_TOKEN`.
  - Step outputs reach shell scripts through environment variables instead of
    `${{ }}` expansion inside `run:`.
  - The contributors workflow no longer persists its checkout token.
- **OpenSSF Scorecard** runs weekly and publishes its results to code scanning.
- **Quarantine:** Dependabot and the pinned CI binaries adopt a new upstream
  release only after it is seven days old. See
  [dependency and workflow audit](../update-audit.md).
- **Contributors:** the README avatar grid excludes automation accounts that
  GitHub reports as regular users.
- See [SECURITY.md](../../.github/SECURITY.md) for the full list and for how
  to verify a release.

## Maintenance and validation

- `scripts/reload-plugin` checks the manifest and locale JSON, the qmldir types,
  the JavaScript modules and leftover conflict markers before it unloads the
  live widget. A broken checkout now leaves the running widget untouched.
- Provider retries keep the configured history retention (`AIOC_HISTORY_MAX`).
- The native UI smoke now runs against DankMaterialShell v1.6.3 and installs
  `jq` in its Arch container. Without `jq` the widget never enabled refreshes
  there, so the real-refresh steps could not run.
- New suite `tests/test-claude-profiles.sh` covers three accounts with isolated
  caches, reordered requests, readiness, invalid definitions and a symlinked
  directory, all offline. `tests/test-widget-runtime.sh` drives both features
  together through real refresh and retry processes, settings reconstruction,
  overrides and cleanup. `tests/test-dms-reload.sh` covers the fail-closed
  reload, and `tests/test-workflow-dependencies.sh` now enforces the security
  workflow contract.
- All 31 offline suites pass, along with:
  - Shell syntax checks and shellcheck.
  - The metadata and changelog gates.
  - `qmllint`, actionlint and zizmor.
  - gitleaks and TruffleHog over the full history.
  - The packaging checks.
  - The real DMS UI suite under headless sway.

## Limitations

- Profiles are read-only views of each account. The plugin never signs an
  account in or out, and never refreshes its token.
- With **Show remaining quota** on, providers that report an absolute value
  (for example OpenRouter's `5 / 50 requests` or a prepaid balance) keep that
  text, while their bar shows the remaining share.
- The settings editor manages up to 16 profiles.
- Moving the native UI smoke to DankMaterialShell 2.0 is a separate
  compatibility change.
