# 2.2.0: Spend providers and Gemini CLI quota

This feature release for DMS 2.0 adds four providers (43 in total) and real
per-model quota for Gemini CLI accounts. It also fixes the DankDash card's
last row running into the bottom edge. Settings, Claude profiles, pins and
history carry over unchanged. Version authority remains `plugin.json`; the
published release body comes from the matching section in `CHANGELOG.md`.

## Upgrading

- Requires DMS 2.0 or newer, as 2.1 does. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
  The DMS plugin registry now states this constraint
  ([duxlabs-dev/dux-plugin-registry#1095](https://github.com/duxlabs-dev/dux-plugin-registry/pull/1095)),
  so DMS 1.6 is no longer offered this update.
- A plugin reload is enough; the manifest did not change shape.
- The new providers are off until you enable them in settings and provide
  their credential.

## User-visible changes

### New providers

([#82](https://github.com/bernardopg/AiOverviewControl/pull/82))

| Provider | Credential | Shows |
| --- | --- | --- |
| [Anthropic API](../providers.md#anthropic-api-claude-console) | `ANTHROPIC_ADMIN_KEY` | Month-to-date and today's spend of a Claude Console organization |
| [OpenAI API](../providers.md#openai-api-platform) | `OPENAI_ADMIN_KEY` | Month-to-date and today's spend of an OpenAI Platform organization |
| [Ollama Cloud](../providers.md#ollama-cloud) | `OLLAMA_API_KEY` | Included monthly credits (or a legacy plan's session and weekly limits) and purchased credits |
| [Vercel AI Gateway](../providers.md#vercel-ai-gateway) | `AI_GATEWAY_API_KEY` | AI Gateway Credits balance and total used |

- The Anthropic and OpenAI cost APIs report no balance or spend limit. Set
  `ANTHROPIC_MONTHLY_BUDGET_USD` or `OPENAI_MONTHLY_BUDGET_USD` to show the
  month as a percentage of your own budget. Subscription limits stay on the
  Claude and Codex cards.
- Admin keys can read organization billing. They are sent only to the
  provider's own API, through a curl config pipe, never on a command line.
  See [Environment variables](../configuration.md#environment-variables).

### Gemini CLI quota

- With a Gemini CLI sign-in, the
  [Gemini card](../providers.md#gemini-google) shows per-model daily quota from
  the Code Assist API the CLI uses. This works for accounts with a Code Assist
  Standard or Enterprise project; `GOOGLE_CLOUD_PROJECT` selects one.
- Google no longer offers Code Assist for individuals to the Gemini CLI. Such an
  account now shows Google's reason instead of "Gemini CLI authenticated".
- An expired CLI token is renewed in memory and never written back to the CLI's
  files. A configured API key still produces the key-check card.

### DankDash card

- The card fits its provider rows into its padded content area, so the last
  row no longer runs into the bottom edge.
- Usage bars use the theme's height, rounding and spacing, like the DMS example
  cards. The DMS registry review flagged the old hardcoded sizes
  ([#84](https://github.com/bernardopg/AiOverviewControl/pull/84)).

## Validation and limitations

- The four new providers are tested against the responses in each provider's
  API documentation, not against live accounts. Please report a card that
  disagrees with your provider's console.
- Gemini CLI quota buckets are tested from the CLI's own response type. The
  ineligible-account path was verified against a live individual account.
- Every shell suite, the QML runtime suite under the pinned DMS, the metadata
  and changelog gates, and the fuzz harnesses pass in CI.
