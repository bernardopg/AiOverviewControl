# 2.1.0: Credits, limit resets and a DankDash card

This feature release for DMS 2.0 brings account billing into the Claude and
Codex cards. You can see extra usage, spend limits, usage credits and held
limit resets, and redeem a reset after a confirmation. Codex telemetry now
shows inference cost the way the Claude card does. A new DankDash overview
card keeps the providers closest to their limits in view. The release also
hardens how credentials and caches are handled. Settings, Claude profiles,
pins and history carry over unchanged. Version authority remains
`plugin.json`; the published release body comes from the matching section in
`CHANGELOG.md`.

## Upgrading

- Requires DMS 2.0 or newer. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
- Run `dms restart` once after upgrading. The manifest changes from a single
  widget to a composite plugin with a DankDash card, and DMS reads the
  manifest only on start-up. Later updates of the dashboard code apply with a
  plain plugin reload (see Fixes).
- The cache directory `~/.cache/AiOverviewControl` is tightened to `0700` on
  the first refresh; nothing has to be deleted.

## User-visible changes

- **Credits & limit resets** for Claude (every profile) and Codex. See
  [The popout](../usage.md#provider-cards).
  - The expanded card shows:
    - whether extra usage is on;
    - the monthly spend limit and what was spent;
    - usage credits, with promotional credits and their expiry (they are used
      before purchased credits);
    - Codex credits and spend control;
    - each limit reset the account holds, with its expiry date, or "No resets
      right now".
  - A ⟳ button next to ★ counts the resets left. It redeems one only after a
    confirmation that shows current usage and warns that resets are
    consumable and cannot be undone. The dialog then reports the outcome. A
    reset the provider refuses uses nothing.
  - Claude resets are redeemed through the same `reset_rate_limits` request
    the Claude Code CLI sends (an undocumented endpoint). Codex resets use
    `account/rateLimitResetCredit/consume`.
  - Both send one request per confirmation with an idempotency id. They are
    never retried and never run on a refresh
    (`providers/reset-provider-limits`).
- **Codex inference cost:** the Codex local telemetry panel prices each
  session row at its model's list price from the LiteLLM table, as the Claude
  card does under a subscription. Uncached input, cached input and output use
  their own rates. A model without a list price stays `—`. See
  [Codex local telemetry](../providers.md#codex-local-telemetry).
- **DankDash card:** an **AI quotas** overview card, sized 1x1 up to 4x2.
  - A 1x1 card shows the provider closest to its limit. Larger cards list
    providers with usage bars and reset times, pinned providers first.
  - It follows **Show remaining quota** and has count and tone options.
  - It reads the snapshot the bar widget writes after each refresh and never
    queries providers itself.
  - See [The DankDash card](../usage.md#the-dankdash-card).

## Security

- **Credentials stay off the command line.** Every adapter passes its secret
  header to `curl` through `--config` on a pipe written by a shell builtin.
  This covers `Authorization`, `x-goog-api-key` and the Cursor session cookie.
  Other local users can no longer read a key with `ps` or
  `/proc/<pid>/cmdline` (CWE-214).
- **Owner-only caches.** Adapters run with `umask 077`, so caches, usage
  history and alert state are readable only by you.

## Fixes

- **Claude after a reboot:** an expired or rejected OAuth access token is
  renewed through the installed CLI (`claude auth status`, for the same
  profile), and the request is retried once. The card no longer says the
  credentials are invalid until Claude Code is started by hand. The plugin
  still never refreshes or writes the token itself.
- **Corrupt Claude credentials:** a truncated `.credentials.json` used to
  crash the helper and hide the local analytics. It is now reported as an
  authentication error. A field with a line break can no longer inject
  `KEY=VALUE` lines.
- **Claude `limits[]`-only responses** are accepted instead of being reported
  as a failed request with HTTP 200.
- **pi:** a malformed session line no longer discards the tokens and cost
  recorded before it.
- **Hot reload:** `dms ipc call plugins reload aiOverviewControl` now applies
  edited dashboard, settings-window, analytics-reader and currency code
  without a shell restart.

## Project

- 80%+ statement coverage of the shell adapters, enforced by the required
  **Statement coverage** check.
- Fuzzing with atheris, directly and under ClusterFuzzLite, now covers both:
  - provider HTTP responses;
  - the local readers: Claude transcripts and credentials, Codex and pi
    session logs, OpenCode SQLite rows, and Grok and Cline auth files.

  The fuzzers also fail on a credential in curl's arguments.
- Releases require a signed tag, verified against
  [`.github/release-signing-keys.asc`](../../.github/release-signing-keys.asc).
- DCO sign-off on every commit, a Code of Conduct, governance, roadmap and
  security assurance documents, and the OpenSSF Best Practices passing badge.

## Validation and limits

- Credits, extra usage and reset grants were checked read-only against live
  Claude and Codex accounts. Redemption is covered by fixtures only, because a
  test redemption would consume a real reset.
- Claude's usage, prepaid-credits and reset endpoints are undocumented and
  account-scoped, and are treated as best-effort.
- Codex costs are API-equivalent estimates, not charges.
