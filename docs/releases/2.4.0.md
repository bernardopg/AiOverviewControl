# 2.4.0: Detect providers, pace and the Claude Code status line

This feature release for Dux Shell 2.0 and 2.1 makes the first minutes easier
and the numbers more current. **Detect providers** finds the AI tools, sign-ins
and API keys already set up on this computer and tracks them in one click.
Every quota bar now shows its **pace**, so a window that will run out before it
resets stands out early. An optional **Claude Code status line bridge** lets
Claude Code hand over its own 5 hour and weekly usage, keeping the Claude cards
current while you work and asking Anthropic's usage endpoint far less often.
The dashboard hero is tidier, and DeepSeek reads the right currency of a
multi-currency balance.

Settings, Claude profiles, pins and history carry over unchanged. Version
authority remains `plugin.json`; the published release body comes from the
matching section in `CHANGELOG.md`.

## Upgrading

- Requires Dux Shell 2.0 or newer; 2.1 is tested. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
- Run `dms restart` once after updating. A running shell keeps its cached copy
  of the bar logic and the settings window, so until the restart the bars show
  no pace and the settings page lacks the new panels. Provider detection lives
  in a new `detect/` directory, which a running shell can load without a
  restart ([#92](https://github.com/bernardopg/AiOverviewControl/issues/92)).
- Nothing needs a decision. Detection only adds providers you tick, and the
  status line bridge does nothing until you put it in Claude Code's settings.
- A checkout install now copies `detect/` too; see
  [Installation](../installation.md#install-from-a-checkout).

## Detect providers

([#120](https://github.com/bernardopg/AiOverviewControl/pull/120))

A new install used to start from three default providers and a catalog of 44
IDs to choose from. Now:

- 🔍 next to ❤ in the dashboard header, and a button on the empty dashboard,
  open **Detect providers** over the dashboard. The top of the **Providers**
  settings group embeds the same panel.
- The check covers the whole catalog and names what it found for each
  provider: `DEEPSEEK_API_KEY is set`, `Signed in · ~/.codex/auth.json`,
  `Local data · ~/.9router/db/data.sqlite`, `Keyring entry configured`.
  Those providers are listed under **Ready to track** and ticked.
- A provider whose command is installed but whose sign-in cannot be confirmed
  without asking the provider (`gcloud installed · sign-in not verified`) is
  listed under **Installed, sign-in not verified** and left unticked, since
  tracking an account that is not signed in only adds an error card.
- Providers you already track are named, not offered again. **Track selected**
  adds the ticked ones to the dashboard and the bar in one save and refreshes.
- It runs locally in about 70 ms, sends no request, reads no key value and
  never unlocks the desktop keyring. Claude profiles are still added in
  **Claude profiles**, with their directory.
- When nothing turns up, the panel says the most common reason: a key exported
  only in a terminal is not visible to the shell.

The readiness helper (`providers/get-provider-health`) now reports this
evidence for every ready provider, and builds its answer with one `jq` call
instead of one per provider, so the settings readiness check is faster too.

See [Detect providers](../usage.md#detect-providers).

## Pace for every quota window

([#119](https://github.com/bernardopg/AiOverviewControl/pull/119))

- Every quota bar with a known window length and reset gets a thin tick where
  an even spend would be by now.
- A flame appears next to the number only when the window, at its average rate
  so far, runs out before it resets.
- Hovering a bar shows the numbers: **Even pace: 40% by now · At this pace:
  used up in 51m · resets in 3h**. The bar pill tooltip adds **used up in … at
  this pace** for such a window.
- The projection waits for 15% of the window and needs 5 points over even use,
  so an early burst stays quiet. Balances, **Unlimited** allowances and windows
  without a reset are not paced. It follows **Show remaining quota**.
- The Claude details panel uses the same bars instead of its own forecast lines.

See [Pace](../usage.md#pace).

## Claude Code status line bridge

([#121](https://github.com/bernardopg/AiOverviewControl/pull/121),
refs [#96](https://github.com/bernardopg/AiOverviewControl/issues/96))

On Claude Pro and Max, Claude Code passes its own 5 hour and weekly usage to
its status line command after each response.
`providers/claude-statusline-bridge` keeps those numbers for the plugin.

- Put it first in the `statusLine` command of `~/.claude/settings.json`,
  followed by the status line you already use. That status line keeps working
  unchanged: it receives the same input, and its output and exit status pass
  through.
- Settings → **Claude profiles** → **Claude Code status line** shows the
  command for this install, with a copy button. The plugin never edits Claude
  Code's settings itself.
- While a reading is less than 10 minutes old, its numbers replace the usage
  endpoint's when they are newer, and the card source reads
  `claude-statusline`. The endpoint is then asked every 15 minutes instead of
  every 2, for what the status line does not carry: the model-scoped weekly
  window, extra usage and limit resets.
- When the endpoint is rate limited with no earlier snapshot, the reading fills
  the card instead of an error. Rejected credentials are still reported.
- Only the two percentages and reset times are kept, owner-only, per
  `CLAUDE_CONFIG_DIR`, in the plugin cache. Nothing is written into
  `~/.claude`. An idle session repeating older numbers neither rolls a reading
  back nor keeps it alive.

See [Claude Code status line bridge](../configuration.md#claude-code-status-line-bridge).

## Dashboard hero

- The stats sit in an even grid, two rows of three when six do not fit on one
  line, instead of a wrapping row that left the last tile alone.
- The hottest provider reads **Peak · Copilot** instead of a bare name.
- The **Last sync** tile is gone: the header line under the title already gives
  the time.
- The status pill only appears when something needs attention; the line above
  the provider's name already says it is live.
- The ambient glow behind the card is blurred instead of a hard-edged disc.

## Provider fixes

- **DeepSeek** ([#117](https://github.com/bernardopg/AiOverviewControl/pull/117)):
  an account carries one `balance_infos` entry per currency (USD and CNY), and
  the adapter read only the first, so a CNY-funded account showed `$0.00` at
  100% used. The first entry that holds funds is now reported, and
  `is_available` is read from the response root, so `false` marks the balance
  depleted even when a total is positive.

## Maintenance

- **New suites:** `tests/test-provider-detect.sh` (detection evidence per
  source, `~` paths, no key values) and `tests/test-claude-statusline.sh`
  (bridge recording and chaining, adapter preference, fallback and expiry).
  The QML smoke and the native UI suite cover the detection panel, the pace
  model and the status line panel.
- **Hot-upgrade layout:** `detect/` is frozen alongside the root and `lib/`;
  the metadata gate, release packaging and `scripts/reload-plugin` know about
  it, and `scripts/reload-plugin` resolves JavaScript imports against the
  importing file's directory.

## Validation and limitations

- Every shell suite, the QML runtime suite under the pinned Dux Shell 2.1.0,
  the metadata, changelog and coverage gates and the fuzz harnesses pass in CI.
- **Verified live:**
  - Detect providers on a real machine with 18 ready providers.
  - The status line bridge chained in front of an existing status line, with
    real Claude Max rate limits: the card read the bridge's newer numbers and
    matched the endpoint's resets.
- Detection sees the shell's environment, not a terminal's. A key exported
  only in `~/.zshrc` is not found until the session imports it.
- Claude Code sends no rate limits on API-key sign-ins or before the first
  response of a session; the plugin then uses the endpoint as before.
