# 2.5.0: OpenRouter balances, Ori and plain amounts

This feature release for Dux Shell 2.0 and 2.1 lets the **OpenRouter** card
headline money left instead of the key limit: the key's balance against its
spending cap, or the account's credits as openrouter.ai shows them
([#127](https://github.com/bernardopg/AiOverviewControl/issues/127)). A new
**Ori** provider tracks OpenRouter's coding agent from its local session files.
Balances, spend and coding-agent telemetry with nothing to compare against now
read as plain amounts in the neutral colour, without a usage bar, instead of a
green `0%`. The README gains a new product video, banner, dashboard gallery and
registry screenshot.

Settings, Claude profiles, pins and history carry over unchanged. Version
authority remains `plugin.json`; the published release body comes from the
matching section in `CHANGELOG.md`.

## Upgrading

- Requires Dux Shell 2.0 or newer; 2.1 is tested. DMS 1.6 users stay on
  [1.22.0](https://github.com/bernardopg/AiOverviewControl/releases/tag/v1.22.0).
- Run `dms restart` once after updating, so the bar, the dashboard and the
  settings window load the new rendering together.
- Nothing needs a decision. **OpenRouter main bar** defaults to **Key limit**,
  the behaviour of 2.4. Ori is offered by **Detect providers** when its session
  directory or the `ori` command is present, and is never added on its own.
- `OPENROUTER_MANAGEMENT_KEY` (or the `AIOC_VAULT_OPENROUTER_MANAGEMENT` keyring
  entry) is optional. Without it, the account view uses `OPENROUTER_API_KEY`.

## OpenRouter main bar

Settings → Providers → **OpenRouter main bar** picks what the card's main bar,
the bar pill and the card header show. The adapter receives it as
`AIOC_OPENROUTER_VIEW`.

| View | Source | Shows |
| --- | --- | --- |
| **Key limit** (default) | `GET /api/v1/key` | The key's spending cap for the current window, or the daily `:free` model allowance of an uncapped key |
| **Key balance** | `GET /api/v1/key` | What is left of the key's cap, in dollars, with a bar for the share already spent. An uncapped key has no such balance and keeps the key-limit bar |
| **Account credits** | `GET /api/v1/credits` | `total_credits - total_usage`, the balance on openrouter.ai/credits. A negative balance reads `-$1.50` |

- OpenRouter's API reference lists `/credits` as management-key only, yet it
  answers an ordinary inference key with the same totals the website shows
  (verified live on 2026-11-16). The adapter asks with `OPENROUTER_API_KEY`, or
  with the management key when one is set.
- If the route refuses, the card keeps the key-limit bar and its credits line
  names the fix (`Account balance needs a management key
  (OPENROUTER_MANAGEMENT_KEY)`). It is not a card error.
- A view change refreshes at once only when OpenRouter is tracked.
- The settings preview shows the amount for the balance views, and
  **Diagnostics and tests** gains a command that runs the OpenRouter adapter
  with the chosen view.

See [OpenRouter views and Ori](../providers.md#openrouter-views-and-ori) and
[Configuration](../configuration.md).

## Ori

Ori is OpenRouter's coding agent CLI. The new `ori`
provider (kind **Agent**, coverage **Analytics**):

- Sums the cumulative cost and tokens Ori writes per session to
  `~/.ori/global/.ori/logs/sessions/<id>/metadata.json` into **Today**, **Week**
  (the last 7 days) and **Month** (the calendar month).
- Names the latest model in the account line and the sign-in method from
  `~/.ori/config.json`. The credits line counts the
  sessions.
- Reads only those files. Ori's SQLite stores and its encrypted OAuth or API key
  under `~/.ori/auth` are never opened, and no request is sent.
- A session that reported no cost makes the window's cost unknown rather than
  partial. With no sessions yet, the card says **No Ori sessions recorded yet**.
- **Detect providers** finds it from the session directory or the `ori`
  command; **Diagnostics and tests** gains a command that runs the adapter.

## Plain amounts

A number only earns a bar and a warning colour when there is something to
compare it with.

- A prepaid balance with no cap, budget or goal (Kimi, DeepSeek, Cline, Ollama
  Cloud purchased credits, Vercel AI Gateway, xAI prepaid, OpenRouter account
  credits) shows its amount in the neutral text colour. The card draws no usage
  bar and the header ring stays empty, even under **Show remaining quota**. Only
  a used-up balance turns red.
- Spend and telemetry readings follow the same rule: OpenRouter's **Spent
  today** and week lines, an uncapped OpenRouter key, Anthropic and OpenAI
  month-to-date spend without a budget, every pi, Ori, Hermes, OpenCode (local),
  9Router and Cloudflare window, and status lines such as NVIDIA's or Kimi's
  voucher/cash split. The card header shows the amount (`$0.01 · 11.5K tok`)
  instead of a green `0%`.
- These readings no longer count toward the fleet's average load.
- A balance measured against a cap keeps the bar and the usage colours
  (OpenRouter **Key balance**), and so does Anthropic or OpenAI spend once a
  monthly budget is set.
- The rule applies to the bar pill and its tooltip, the card header and ring,
  the history line, the Dashboard card and the settings preview.

Adapters mark these windows with a new optional `hasLimit` field: `true` for a
balance measured against a cap, `false` for a non-balance reading with nothing
to compare against. See [Architecture](../architecture.md).

## Fixes

- The OpenRouter card no longer asks `GET /api/v1/activity` with an ordinary
  key. That route rejects every key except a management key (HTTP 403 `Only
  management keys can fetch activity for an account`), so the 30-day top-models
  line never appeared and each refresh sent a request bound to fail. With a
  management key, the top models come back.
- The OpenRouter week line no longer embeds the English words "Week" and
  "Month" in its value; its translated label already names both windows.
- The **OpenRouter** logo is the current "OR" glyph from OpenRouter's brand
  page instead of the old routing-arrows mark, flattened to one `currentColor`
  path. Its source and hash are in `assets/provider-logos/SOURCES.md`. The Ori
  card uses it too.

## Translations

## Validation and limitations

- `tests/test-openrouter.sh` covers the three views, key balance with and
  without a cap, account credits with an inference and a management key, a 403
  with and without a management key, a 502 HTML body, an empty body, a negative
  balance, an unknown view, `/activity` only with a management key, and
  `hasLimit` on every window.
- `tests/test-ori.sh` (new, registered in CI) covers the windows, unknown and
  tiny costs, a damaged file, a missing timestamp, the login method, a missing
  directory with and without the CLI, readiness and the stub entrypoint.
- `tests/test-spend-providers.sh` checks `hasLimit` for Anthropic and OpenAI
  with and without a budget and for Vercel; `tests/test-widget-runtime.sh`
  checks the plain-amount colours, text, settings preview and the OpenRouter
  view setting under a native Dux Shell UI.
- Live: the account view on a real key showed the website balance in the bar
  pill, a real Ori session showed its cost and tokens, and the spend lines and
  the pi, Ori and OpenCode cards read neutral with no bar.
- Not verified live: the management-key path for `/activity` and `/credits`;
  no management key was available. OpenRouter may enforce its documented
  management-only rule for `/credits` later; the card then keeps the key-limit
  bar and names the fix.
- Ori's session format is not a published contract. The adapter reads only
  documented fields it found on disk and skips a damaged file.
